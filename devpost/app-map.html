🛡️ Agentic Rule Enforcer — App Map

A reference architecture map and reproducible guide for the Agentic Rule Enforcer proof of concept built during the Devpost Build With AI: Basics hackathon.

1. Plain-Language Overview

Agentic Rule Enforcer intercepts code produced by autonomous AI coding assistants before it gets committed. It parses human-readable Markdown policies from agent_rules.md, inspects target code line-by-line for high-risk patterns (secrets, terminal logs, scope leaks), generates interactive unified diffs for developer review, takes safety backups, and allows single-command rollback.

3. Code Tour & Key Navigation Stops

Stop 1: Rulebook Parsing (enforcer/parser.py)

Anchor: parse_rulebook_content(content: str)

Reads Markdown blocks starting with ### RULE-... and dynamically extracts attributes (Severity, Pattern, FileTypes, Fix). Compiles raw regex strings into executable matchers.

Stop 2: Codebase Scanning (enforcer/scanner.py)

Anchor: scan_file(file_path: Path, rules: List[Rule])

Evaluates applicable files line-by-line, isolates violations, extracts 1-indexed line numbers, surrounding context lines, and assigns automated fix blueprints.

Stop 3: Interactive Diff & Remediation (enforcer/remediator.py)

Anchor: compute_file_fix(file_path: Path, violations: List[Violation])

Generates unified Git-style diffs using difflib. Sorts line edits in reverse order to prevent line-offset corruption, displays color-coded diffs, and requests developer confirmation before invoking backup.py and updating files.

4. "To Change This, Start Here"

  • Add a new rule without writing code: Open agent_rules.md and append a new ### RULE-... block.
  • Change terminal colors or table layout: Inspect enforcer/ui.py (functions colorize and render_scan_results).
  • Add a new auto-remediation pattern: Open enforcer/remediator.py and enhance compute_file_fix.
  • Change snapshot backup location: Modify BACKUP_ROOT in enforcer/backup.py.

5. A Practice to Reuse

Plan-First Verification: Defining observable acceptance criteria and small end-to-end slices before writing code guarantees that every component can be mechanically verified. By building the scanning and backup mechanisms before adding remediation, we eliminated the risk of destructive file modifications.

6. How to Run & Verify

# 1. Initialize rulebook
python -m enforcer.cli init

# 2. View active rules
python -m enforcer.cli rules

# 3. Scan sample code
python -m enforcer.cli scan examples/sample_agent_code.py

# 4. Preview and apply safe fix
python -m enforcer.cli fix examples/sample_agent_code.py

# 5. Restore original state
python -m enforcer.cli rollback

# 6. Run all automated unit tests
python -m unittest discover -s tests
